# C64 cheat-sheet (stock + REU) for ISO64

Sources and confidence marks are in `docs/research/c64.md`. This page is the working summary.

## Timing

| | PAL | NTSC |
|---|---|---|
| Clock | 985,248 Hz | 1,022,727 Hz |
| Cycles per line × lines | 63 × 312 | 65 × 263 |
| **Cycles per frame** | **19,656** | **17,095** |

- **Badline:** costs 40–43 cycles. It happens on lines `$30–$f7` where `(raster & 7) == YSCROLL` and the display is on. That's 25 per frame.
- **Sprites:** ~2 cycles per sprite per line, plus overhead. 8 sprites ≈ 19 cycles per line.
- **Measured in VICE:** a 1000-byte REU fetch over 16 lines costs +84 cycles with the screen on and +505 with 8 sprites as well. The harness doesn't model this, so add it by hand.

## ISO64 C64 memory map (DESIGN.md)

| Range | Use |
|---|---|
| `$0801-$3dff` | Code |
| `$3e00` / `$3f00` | `COLM` / `ROWM` |
| `$4000` | Screen A |
| `$4400` | Sprites |
| `$4c00` | Map |
| `$5a00-$5fff` | Free |
| `$6000` | Bitmap A |
| `$8000-$bfff` | `TILES` (BASIC out) |
| `$c000` | Screen B |
| `$c400` | Sprite copy |
| `$c800` | Colour shadow |
| `$e000` | Bitmap B (RAM under the KERNAL) |

- Banks 1 and 3 are flipped by a single write to `$dd00`, with `$d018 = $08`.
- While drawing: `$01=$35`, `sei`, and the NMI vector points at an `rti`.

**Zero page:**
- shared: `$02-$5f`;
- C64 layer: `$60-$87` (REU tier `$60-$69`, smooth walk `$6a-$87`).

## VIC-II essentials

| Reg | Use |
|---|---|
| `$d011` | Bit 7 raster bit 8, bit 5 bitmap, bit 4 display enable, bits 0–2 YSCROLL |
| `$d012` | Raster line |
| `$d016` | Bit 4 multicolour, bits 0–2 XSCROLL, bit 3 40/38 columns |
| `$d018` | Screen and bitmap base within the bank |
| `$dd00` | Bits 0–1 = VIC bank (inverted) |
| `$d015` | Sprite enable |
| `$d01b` | Sprite-behind-background priority (multicolour pixel pairs `10` and `11` count as foreground) |
| `$d01c` | Sprite multicolour |
| `$d025` / `$d026` | Shared sprite colours |
| `$d027-$d02e` | Sprite colours |
| `$d020` / `$d021` | Border / background |

**Multicolour bitmap pixel pairs:** `00` = `$d021`, `01` = screen RAM high nibble, `10` = screen RAM low nibble, `11` = colour RAM (`$d800`, not banked).

## REU (`$df00-$df0a`)

| Reg | Use |
|---|---|
| `$df00` | Status (bit 6 EOB, bit 5 verify fault, bit 4 size; reading clears) |
| `$df01` | Command: bit 7 exec, bit 5 autoload, bit 4 no-`$ff00`-trigger, bits 1–0 = 00 stash / 01 fetch / 10 swap / 11 verify. ISO64 uses `$b0` stash and `$b1` fetch |
| `$df02/3` | C64 address |
| `$df04/5/6` | REU address |
| `$df07/8` | Length (0 = 64 KB) |
| `$df09` | IRQ mask |
| `$df0a` | Bit 7 fix the C64 address, bit 6 fix the REU address |

**Measured in VICE:**
- stash, fetch and verify cost 1 cycle per byte, plus ~3 cycles of setup;
- swap costs 2 cycles per byte;
- the transfer pauses during badlines and sprite DMA.

**Blitter idioms:**
- **Fill:** fetch with the REU address fixed (ISO64 clears rows by repeating REU byte `$00000`, which is always 0).
- **Stream a table into one register:** fetch with the C64 address fixed.
- **Compare:** verify (bit 5 is set on a mismatch).
- **Use autoload:** then only the addresses and the command change per row.
- **Detection:** write two patterns to `$df02-$df05` and read them back (a stock C64 reads open bus).

**ISO64 REU world:**
- 148×82 cells: bitmap at `$00000` (82 × 1184), screen at `$18000`, colour at `$1c000`. 121,360 bytes in all.
- Built at map load by `world_build` (~5.5M cycles).

## Other expansions

| Expansion | Facts |
|---|---|
| GeoRAM | 256-byte window `$de00-$deff`; page `$dffe`, 16 KB block `$dfff`. CPU copy ~8–10 cycles per byte |
| EasyFlash / KFF | 1 MB flash in 16 KB banks at `$8000-$bfff`. Bank `$de00`, mode `$de02`. 256 bytes of RAM at `$df00`. EAPI for flash writes. KFF disk emulation is KERNAL-vector based, so **no custom fast loaders** |
| sd2iec | KERNAL protocol speed, JiffyDOS and several fast-loader protocols. **No 1571 burst** (unconfirmed) |
| SuperCPU | 65816: **no illegal opcodes**. `$d07a`/`$d07b` speed switch |

## CPU cost table (6502 cycles)

| Operation | Cycles |
|---|---|
| `lda abs,x` / `lda abs,y` | 4 (+1 on a page cross) |
| `sta abs,x` | 5 |
| `lda (zp),y` | 5 (+1 on a page cross) |
| `sta (zp),y` | 6 |
| `lda zp` / `sta zp` | 3 |
| `inx` / `dex` | 2 |
| Taken branch | 3 (+1 on a page cross) |
| `jsr` + `rts` | 12 |
| IRQ entry + `rti` with A/X/Y saved | ~40+ |

**ISO64's masked cell loop:**
- `lda (rbp),y / and (mp),y / ora (cp),y / sta (rbp),y / iny` = **23 cycles per byte**.
- With self-modified absolute operands it's ~19, or ~17 with interleaved data.
- The opaque copy `lda (cp),y / sta (rbp),y / iny` costs 13.

**Illegal opcodes:**
- Stable and fine on 6510/8502: LAX, SAX, DCP, ISC, SLO, RLA, SRE, RRA, ANC, ALR, ARR, SBX. Enable them with `.setcpu "6502X"`.
- Unstable, never use: ANE, LXA, SHA, SHX, SHY, TAS.
- Not available on 65C02/65816 (SuperCPU) or in MEGA65 native mode.
- The Ultimate's FPGA core is unverified.

## Tricks catalogue (what each one costs ISO64)

| Trick | Cost / constraint |
|---|---|
| Raster IRQ splits | Needed for music, the multiplexer and a hires UI split. The engine has IRQs off while drawing, which must change first (OPPORTUNITIES X-1) |
| Sprite multiplexer | Sort by Y, re-use sprites after 21+ lines. Figures closer vertically can't share one |
| `$d01b` priority | Cheap approximate "behind walls". Occluding art must use pixel pairs `10`/`11` |
| FLD / line crunch / VSP / AGSP | Hardware scroll with no copying. **VSP can crash some C64s**; AGSP would also scroll the side panels |
| FLI family | Costs the CPU 40 cycles per line. Not affordable on stock; an Ultimate-only idea at most |
| 38-column / 24-row modes | Don't fit the inset viewport (columns 8–31, rows 1–18), which is why the REU walk masks edges in software |
| Colour RAM | Can't be banked: copy it after the flip (stock) or DMA it (REU), finishing before line 59 |
